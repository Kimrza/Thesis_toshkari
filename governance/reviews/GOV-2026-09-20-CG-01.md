### Recommendation 1 — 5,964 December accesses reconcile to zero registry rows

- **Category**: Compliance · **Severity**: Critical (`BLOCKER`)
- **Finding ID / reviewer**: VAL-1 + DATA-3 + CHAIR-5 + VAL-2 + VAL-5 — Validation Auditor, Data/Reproducibility, Chair (three seats, independently)
- **TEC gate / AI-DLC stage**: G-05, G-06 (WS-18, TA-18) / 3.5 `governance-guards`, `foundation`
- **Requirement**: Vision §8.3 ("recorded **in the experiment registry** with `locked_test_accessed = true`"); TE §13.4; R-19
- **Evidence**: `evidence/test_run_access_log.jsonl` — 5,964 rows, all `locked_test_accessed: true`, all `retrieved_at_utc == "recorded-at-call-time-by-the-runner"`, two `run_id`s (`test_release_hashes` 5,640, `test_acquisition_window` 324). `artifacts/registry/experiment_registry.jsonl` — 28 rows, `grep -c '"locked_test_accessed": true'` = **0**. `src/data/experiment_registry.py:651-662` raises on the first orphan. Every call site of `reconcile_access_records` passes `tmp_path` fixtures; none passes the real pair.

**Issue** — Every December restricted-root read since 2026-08-28 exists only in a sidecar the governing document does not name, with a placeholder retrieval timestamp, unreconcilable by `run_id`; and the both-way join built to catch exactly this has never run on the production artifacts.

**Importance** — Vision §8.3 makes the registry the artifact from which a G-06 reviewer establishes when the locked set was touched. A register showing zero accesses beside a log showing 5,964 is the worst possible pairing to present at a viva.

**Risk** — A genuine unauthorised access would be one row among 5,964 identical-looking ones, and the control that would name it never executes.

**Possible Solutions**
1. Declare the two suite runners as named `known_orphans`, fix the placeholder in both producers, add one test running the join on the real pair.
2. Separate the logs: test runs append to a gitignored `artifacts/` path; `evidence/test_run_access_log.jsonl` is reserved for real accesses. Archive the current file as superseded, never delete.
3. Emit a registry event per suite run so no orphan class exists.

**Comparison** — (1) is minimal and truthful about what these reads are, and keeps the friction that a future unregistered runner must be added by hand. (2) restores the log's evidentiary meaning outright and matches the project's supersede-never-delete practice. (3) floods a registry TE §13.4 scopes to *experiment runs* with thousands of non-experiment rows; not recommended. (1) and (2) are close; (2) is stronger, (1) cheaper.

**Recommendation** — (1) as the smallest acceptable remediation, (2) as the durable fix. Both require a real `retrieved_at_utc`. Never back-fill a registry row — the function forbids it and must keep forbidding it.

- **Closure evidence**: a passing join on the real pair with printed `expected_orphans`; every new row carrying a parseable `retrieved_at_utc`.
- **Owner / due gate**: project decision owner + `foundation`/`governance-guards` — before G-05.
