# R-60 hand-check — GIM interpolation, one worked example

Dated 2026-09-26. Worked by hand from the real acquired file below; every
number is traceable to a specific line of that file. This is the artifact
the generation gate consumes per the runbook — it is **not** a Q-15 freeze
act and doesn't pick a rule; it demonstrates that all three candidate rules
are hand-checkable and shows their numeric spread at one concrete point.

(day-of-year 100 = 2022-04-10, January–November, not December).
SHA-256 (from the acquisition manifest): see
`evidence/gim_code_final_2022/sha256_manifest.json` key `codg1000.22i.Z`.

## Target

## Bracketing grid points

Lat brackets 32.778987°: row 35.0° (above) and row 32.5° (below) —
`(87.5 - 32.778987) / 2.5 = 21.888...`, so between grid rows 21 and 22.
Lon brackets 35.022987°: column 35.0° (below) and 40.0° (above) —
`(35.022987 - (-180)) / 5 = 43.004...`, between grid columns 43 and 44.

Raw grid values (0.1 TECU), quoted verbatim from the decompressed file:

| 1 (00:00) | 32.5° | 186 | 187 |
| 1 (00:00) | 35.0° | 175 | 176 |
| 2 (01:00) | 32.5° | 182 | 182 |

(Each is the 12th/13th number, 0-indexed positions 11 and 12, on the third

## Rule A — nearest grid point, nearest map epoch

Nearest epoch to 00:20 is map 1 (00:00, Δ20min) over map 2 (01:00, Δ40min).
Nearest lat: 32.5° (Δ0.279°) over 35.0° (Δ2.221°).
Nearest lon: 35.0° (Δ0.023°) over 40.0° (Δ4.977°).
**Result: 186 × 0.1 = 18.6 TECU.**

## Rule B — bilinear spatial + linear temporal

Fractional weights:
`f_lat = (32.778987 - 32.5) / 2.5 = 0.111595`
`f_lon = (35.022987 - 35.0) / 5 = 0.004597`
`f_t = 20/60 = 0.333333`

Bilinear at map 1:
`V1 = (1-f_lat)(1-f_lon)(186) + (1-f_lat)(f_lon)(187) + f_lat(1-f_lon)(175) + f_lat·f_lon(176)`
`= 0.888405×0.995403×186 + 0.888405×0.004597×187 + 0.111595×0.995403×175 + 0.111595×0.004597×176`
`= 164.484 + 0.764 + 19.439 + 0.090 = 184.78` (0.1 TECU)

Bilinear at map 2, same weights, values 182/182/168/169:
`V2 = 0.884321×182 + 0.004084×182 + 0.111081×168 + 0.000513×169`
`= 160.947 + 0.743 + 18.662 + 0.087 = 180.44` (0.1 TECU)

Temporal blend: `V_B = V1×(1-f_t) + V2×f_t = 184.78×0.6667 + 180.44×0.3333 = 183.33`
**Result: 183.33 × 0.1 = 18.333 TECU.**

## Rule C — bilinear on consecutive rotated maps (IONEX §4 method)

Earth-rotation correction rate: 360°/24h = 15°/hour. Per Schaer et al.
(IONEX 1.0, 1998): shift map 1's effective longitude forward by the elapsed
time since its epoch, and map 2's effective longitude backward by the
remaining time to its epoch, before the same bilinear lookup.

`shift_1 = +15°/h × (20/60 h) = +5.0°` → effective lon for map 1: `35.022987 + 5.0 = 40.022987°`
`shift_2 = -15°/h × (40/60 h) = -10.0°` → effective lon for map 2: `35.022987 - 10.0 = 25.022987°`

Map 1 now brackets lon 40.0°/45.0° at lat 32.5°/35.0° — new grid values
(same source lines, columns 12/13): 187, 184 (lat 32.5), 176, 174 (lat 35.0).
`f_lon1 = (40.022987-40.0)/5 = 0.004597` (unchanged — a whole-5° shift
preserves the fractional offset), `f_lat` unchanged.
`V1_rot = 0.884321×187 + 0.004084×184 + 0.111081×176 + 0.000513×174`
`= 165.368 + 0.752 + 19.550 + 0.089 = 185.76` (0.1 TECU)

Map 2 now brackets lon 25.0°/30.0° at lat 32.5°/35.0° — grid values
(columns 9/10): 178, 181 (lat 32.5), 163, 166 (lat 35.0).
`f_lon2 = (25.022987-25.0)/5 = 0.004597`
`V2_rot = 0.884321×178 + 0.004084×181 + 0.111081×163 + 0.000513×166`
`= 157.409 + 0.739 + 18.106 + 0.085 = 176.34` (0.1 TECU)

Temporal blend (same f_t = 0.333333 as rule B — rotation changes the
spatial lookup, not the time weight):
`V_C = 185.76×0.6667 + 176.34×0.3333 = 182.62`
**Result: 182.62 × 0.1 = 18.262 TECU.**

## Comparison at this one point

| Rule | Value (TECU) | Δ from C |
|---|---|---|
| A (nearest) | 18.600 | +0.338 |
| B (bilinear, no rotation) | 18.333 | +0.071 |
| C (rotated bilinear) | 18.262 | — |

At this single instant the rotation correction (B vs C) is small
(~0.07 TECU, ~0.4%) relative to the nearest-neighbor crudeness (A vs C,
~0.34 TECU, ~1.9%) — consistent with the decision document's own framing
that the rotation term is "modest" while nearest-neighbor is a "deliberately
crude bound." **This is one instant at one station and is not a claim about
typical or worst-case magnitude across ARUC/BSHM/NICO or the full Jan–Nov
period** — it demonstrates the arithmetic is hand-checkable and reproducible,
which is what this gate exists to verify, not a rule recommendation by
itself.
