- 2026-09-13T13:30:00Z — **NEW CRITICAL, found by execution rather than reading: on Windows every stage script and the walking-skeleton orchestrator exit 0 regardless of outcome, discarding their own non-zero exits.** Observed: `run_walking_skeleton.py --fixture plumbing_7day` prints `preflight refusal: …` on stderr and exits **0**; identical for `--fixture scientific_1month`, `scripts/00_acquire_prepared_vtec.py` and `scripts/04_build_external_products.py`. Verified two independent ways (direct shell `$?` and `subprocess.run(...).returncode`). The source is not at fault in intent: the handler at `scripts/run_walking_skeleton.py:1073-1078` does `return 1` under the comment "terminate non-zero", and all nine entrypoints use `sys.exit(main())`. **The cause is the R-05 re-exec.** `src/data/config.py:994-1018` `ensure_process_determinism` calls `os.execv(sys.executable, [sys.executable, *argv])`, and its docstring asserts "On Windows, `os.execv` spawns a replacement process and the parent exits — callers observe one logical run either way." The second half is false. Isolated probe (`scratchpad/execv_probe.py`): parent execs, child intends `sys.exit(1)`, **observed process exit code is 0**. On Windows `execv` spawns a detached child and terminates the parent with 0 without awaiting it, so the child's status is unreachable; on POSIX `execv` genuinely replaces the image and the code propagates. Consequences: TE §13.2's ordered clean-run contract cannot detect a failing step; TE §9.2's "both fixtures must pass before any full-year job" gate cannot distinguish a pass from a refusal, since the orchestrator returns 0 either way; and `project.md` § Mandated's "ALWAYS surface an integrity failure … with an explicit exit" is defeated at the root — the explicit exit is written and then discarded. **Platform split is the reason this survived**: Kaggle is Linux and behaves correctly, `local` is Windows and does not, so of the two authorised platforms (TC-03c) the local one silently reports success. It went unfound because no prior session had a working interpreter to run anything with.
